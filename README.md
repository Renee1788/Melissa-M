## Hi there 👋
Artemis Financial is a financial consulting firm that offers savings, retirement, investment, and insurance plans to individuals and handles sensitive customer data through a Restful web API. As a developer at Global Rain, I was asked to assess and strengthen the security of that application, mainly by protecting data in transit and verifying data integrity, which led to enabling HTTPS and adding a SHA-256 checksum endpoint to the Spring Boot code base.

In the vulnerability assessment, I did well by combining manual code review with static testing from the Maven OWASP dependency check plug in. I mapped each finding to the seven areas of security and to CVE and CWE references, then paired each with a specific mitigation. Coding securely matters because a single flaw, such as an injectable input, an outdated library, or an unencrypted connection, can expose customer data. Security adds value to a company's overall well being by protecting client trust, reputation, regulatory standing, and finances, and fixing issues early costs far less than responding to a breach.

The most challenging part was reading the dependency check results and separating real risks from false positives, but that work was also the most helpful because it taught me to evaluate severity and context rather than react to every flagged item.&nbsp;

I increased layers of security by generating a keystore with Java Keytool and configuring SSL/TLS so traffic runs over HTTPS on port 8443, by adding the SHA-256 checksum to verify integrity, and by updating vulnerable dependencies. In the future, I would use a more systematic approach that pairs the process flow diagram and a risk-based ranking of findings (such as CVSS scores) with static analysis tools, dependency scanning in a CI pipeline, and dynamic testing, to decide which mitigation techniques to apply first.&nbsp;

To make sure the code stayed functional and secure, I ran functional tests to confirm the application was still built and the /hash endpoint and secure connection returned the expected results. I then did secondary testing by re running the dependency check scan and reviewing the refactored code to confirm that no new vulnerabilities had been introduced.&nbsp;

Resources and practices that will help in future work include the OWASP dependency check plug in, the NVD and CVE databases, Java Key tool, Eclipse for manual review, input validation and allow-listing, safe exception handling, secure by default configuration, and following industry standards such as the OWASP guidelines.&nbsp;

To show future employers, I would share the Project One vulnerability assessment report and the Project Two refactored code and documentation, since together they show that I can interpret client needs, identify and prioritize risks, implement encryption and integrity controls, test my own work, and communicate the results clearly in writing.
